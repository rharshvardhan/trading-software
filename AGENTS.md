## Product and strategy boundaries

- Build a Python backend with FastAPI and a terminal interface. The user later requested a bare-minimum React and Tailwind UI (`frontend/`, `specs/SPEC.md` section 13 U1); keep it plain and keep all logic in the backend.
- Keep one shared strategy implementation for the terminal and API interfaces.
- Preserve the separate session-extreme qualification and four-candle breakout range. The entry candle is the candle immediately after the confirmed breakout candle.
- The Dhan adapter follows `specs/SPEC.md` section 13. Credentials live only in the git-ignored `.env`; never print, log, or commit them, and never call Dhan from tests. Do not fabricate security identifiers, provider responses, or complete historical fixtures from partial chart observations.
- The 09:45 window's initial stop-loss level is implemented (`specs/THREE_CANDLE_0945_STOP_LOSS_SPEC.md`). Later SHORT and LONG 60% target formulas are documented only (`specs/HIGHEST_HIGH_60_PERCENT_TARGET_SPEC.md`). Other windows' stop-loss prices and all stop-hit, target-hit and exit execution rules remain undefined; keep the currently unavailable risk outputs `null` rather than adding defaults, and never compute a hit, exit or loss from a price level alone.
- A valid setup can subsequently fail. Do not classify every qualifying stock as a profitable trade or invent a cause of failure from chart movement alone.
- This project reports signals and reference prices. Order placement is outside the requested scope.
